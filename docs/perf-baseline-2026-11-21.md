## 원인 (3회차 기준)
- 종목 데이터를 서버가 아닌 브라우저가 가져옴: 첫 HTML에는 샘플 데이터(삼성전자 207,000원 등)가
  들어 있고, 로드 후 `/api/universe`(44KiB, 전체 종목)와 `/api/investor-trend`(86KiB)를 받아 교체.
  LCP 요소가 이 데이터가 들어온 뒤에 나타나는 문단이라 LCP가 5초대.
- CLS: 샘플 → 실제 데이터로 바뀌며 카드(`rounded-lg bg-white p-4`)가 밀림.
- JS 202KiB(`mobile-screens.tsx`가 통째로 `"use client"`), 사용되지 않는 JS 약 22KiB.
- 글꼴: Inter 48KiB + Pretendard 서브셋 여러 개(각 30~40KiB, CDN, 렌더 차단 CSS 157ms).
- 렌더 차단 CSS 1개(157ms).

## SEO 현황 (Lighthouse가 못 잡는 것)
- 모든 종목 페이지 `<title>`·description이 동일("Stock Advisor").
- 존재하지 않는 종목(`/stock/999999`)이 HTTP 200 (soft 404).
- `/sitemap.xml`, `/robots.txt` 모두 404.
- 서버가 보여주는 값은 샘플 데이터라 크롤러는 실제 시세가 아닌 샘플을 봄.

## 한 일
- `/stock/[ticker]` 정적 생성 + 5분 갱신(ISR). 상위 200종목 미리 생성, 나머지는 첫 요청 때 생성.
- 서버가 DB에서 종목과 같은 업종 종목을 읽어 첫 HTML에 포함 (샘플 값 → 실제 값).
- 종목별 title·description·canonical·Open Graph, sitemap.xml(202개 URL), robots.txt.
- 공시 푸시 로그인 확인(`?from=push`)을 서버 searchParams에서 브라우저 컴포넌트로 이동
  (searchParams를 읽으면 페이지가 요청마다 렌더링돼서 ISR이 꺼짐).
- 데이터 카드(차트·재무·투자자·뉴스)는 서버에서 렌더링하지 않고 스켈레톤만 HTML에 포함
  (정적 생성 중 외부 API 호출 방지).
- 차트 스켈레톤이 실제 카드 높이(258/285px)를 미리 차지하게 해서 CLS 해소.
- 쓰지 않는 Inter 글꼴 제거(48KiB).

## 남은 문제 / 한계
- LCP: Pretendard(CDN 동적 서브셋, 11개 파일 약 280KiB)가 원인. 글꼴 스타일시트를 빼고 재측정하면
  LCP 3.9s, FCP 0.8s, 전송량 455KiB, Performance 84~88. 디자인(글꼴) 선택과 맞바꿔야 하는 부분.
- 없는 종목(`/stock/999999`)은 404 화면 + noindex 지만 HTTP 상태는 200 (루트 `loading.tsx` 때문에
  응답이 스트리밍으로 시작돼 상태 코드를 바꿀 수 없음).
- 값은 로컬 프로덕션 빌드 + Lighthouse 시뮬레이션 기준이라 실제 배포 환경(Vercel, 한국 사용자)과 다를 수 있음.

# 글꼴 자체 호스팅 시험 (Pretendard)

| 방식 | Performance | FCP | LCP |
| --- | --- | --- | --- |
| CDN (이전) | 76 | 1.5s | 6.0s |
| 자체 호스팅 + 번들 CSS + preload | 73 | 2.6s | 6.6s |
| 위 + `font-display: optional` | 73 | 2.6s | 6.6s (변화 없음) |
| **자체 호스팅 + 로드 후 CSS 부착 (채택)** | **75~77** | **0.8s** | 6.6s |
| (참고) 글꼴 없음 | 84~88 | 0.8s | 3.9s |

- 글꼴 CSS가 55KB(92개 `@font-face`)라 번들 CSS에 합치면 첫 화면이 늦어짐 → 로드 후 부착으로 FCP 0.8s.
- LCP는 글꼴 바이트(이 페이지 기준 17개 파일, 약 440KiB)가 원인이라 호스팅 위치로는 안 바뀜.
  줄이려면 글꼴 자체를 줄여야 함(시스템 글꼴 또는 사용 글자만 담은 자체 서브셋).
